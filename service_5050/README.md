# Helmet Pipeline (Service 5050 - Legacy V1)

## Опис концепції (Concept Overview)
Цей проєкт призначений для автоматизованого розрахунку відхилень військових шоломів під час лазерної обрізки на роботизованому комплексі Fanuc. Сервіс 5050 є першою (v1) ітерацією пайплайну.

Головна мета пайплайну: 
1. Взяти еталонний файл координат `.ls` (з робота).
2. Використовуючи 3D-модель шолома та систему комп'ютерного зору (камери), порівняти еталонне (ідеальне) положення шолома з його поточним положенням у просторі (на болванці).
3. Вирахувати вектор зміщення (дельта X, Y, Z та обертання Roll, Pitch, Yaw).
4. Згенерувати новий відкоригований `.ls` файл з новими точками обрізки, які враховують викривлене положення шолома.

## Архітектура (Architecture)
Проєкт складається з:
- **Бекенд (Backend)**: `web/app.py` - Flask-сервер, який слухає на порту 5050 та надає API для запуску Python-скриптів.
- **Фронтенд (Frontend)**: `web/templates/index.html` - веб-інтерфейс, який по черзі (через API) викликає кроки пайплайну та візуалізує результати, а також містить 3D-візуалізатор (Three.js).
- **Скрипти пайплайну (Pipeline Scripts)**: Тека `scripts/` містить розбиті покроково модулі (step00...step10), кожен з яких виконує окрему частину математичних розрахунків або комп'ютерного зору.
- **Робоча папка**: Сервіс очікує наявність папок `input/` (з вхідними `.ls` файлами, 3D моделями, та фотографіями) та `results/` (куди складаються JSON і зображення після кожного кроку). Конфігурація шляхів знаходиться у `pipeline_config.json`.

## Опис файлів-скриптів (Scripts Reference)
Кожен скрипт пайплайну виконується як окремий процес і зберігає свій стан у JSON-файли в папці `results/<session_id>/`.

- `step00_env_check.py` — Перевірка наявності потрібних файлів, папок, та конфігів перед стартом.
- `step01_parse_ls.py` — Парсинг оригінального `.ls` файлу від Fanuc, вилучення координат лінії різу та опорних точок.
- `step02_align_3d_to_ls.py` — Вирівнювання (Alignment) 3D-моделі шолома (.stl) до еталонних точок `.ls` файлу.
- `step03_freeze_space.py` — "Замороження" простору, збереження фінальної матриці вирівнювання Еталону для подальших розрахунків.
- `step04_segment.py` — Використання нейромережі (YOLO/SAM) для сегментації (вирізання масок шолома) на 2D-фотографіях з камер (працює у режимі `etalon` або `current`).
- `step05_project.py` — 2D->3D Проекція. Проектування відсегментованих 2D-масок з камер у 3D-простір для пошуку країв.
- `step06_place_projected.py` (та `step06_fit_pose.py`) — Розміщення проекцій (масок) у 3D-просторі з урахуванням глибини та перевірка їх збігу з 3D-моделлю шолома.
- `step07_fit_etalon.py` — Ітераційне суміщення (Etalon Fit): алгоритмічна підгонка (оптимізація) позиції 3D-моделі так, щоб її контури збігалися з масками з усіх камер. Це міліметрове калібрування еталону.
- `step08_fit_pose.py` — Current Pose Fit: розрахунок відхилень поточних масок (з нових фотографій) відносно еталонних. Пошук кутів нахилу та зсуву шолома.
- `step09b_texture_fit.py`, `step09c_contour_fit.py`, `step09d_ai_reconstruct_fit.py` — Альтернативні/додаткові алгоритми розрахунку відхилень (за текстурою, чистою математикою контурів, або 3D-реконструкцією ШІ).
- `step09_generate_ls.py` / `step07_08_generate_ls.py` — Старі скрипти генерації LS файлів.
- `step10_analyze_results.py` — Фінальний аналіз результатів: порівняння результатів усіх алгоритмів, розрахунок дельти і генерація остаточної матриці трансформації.
- `analyze_mask.py` — Допоміжний скрипт для аналізу контурів.
- `logger.py` — Система логування, яка виводить інформацію у консоль та пише у файл `log_<session_id>.txt` для веб-інтерфейсу.

## Як розширювати для іншого ШІ (Notes for AI Agents)
- **Session ID**: Кожен прогін працює у своїй ізольованій папці `results/<session_id>`. Усі скрипти приймають аргумент `--session <id>`.
- **State Management**: Дані між кроками передаються виключно через JSON-файли в директорії сесії (напр. `step01_ls_points.json`, `step02_alignment.json` і т.д.).
- **Веб-UI (index.html)**: UI використовує polling (`/api/log`, `/api/session_state`), щоб оновлювати стан на екрані. Three.js завантажує JSON-метрики з бекенду для побудови 3D сцени.
- **Додавання нового кроку**: Якщо ви додаєте новий крок, його потрібно: 
  1) створити в `scripts/`, 
  2) додати маршрут у `web/app.py`, 
  3) додати HTML-блок (`step-card`) у `web/templates/index.html` і розширити масив `stepList` у функції відновлення сесії.
