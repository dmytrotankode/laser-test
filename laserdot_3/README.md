## План (робота «під поточні камери»)

1. Розшифрувати 45 фото пульта → `points.csv` (точка, повтор, X..R, фото).
2. Пікселі пронумерованих точок на back/left/top → `pixels.json`
   (автодетект плям + звірка номерів очима, або `laserdot_2/mark.html`).
   Урок 18.08: переплутані підписи 13/19 зіпсували калібровку — перевіряти.
3. Калібровка променевою постановкою (`service_3030/exp_marker_calib.py`:
   промінь інструмента має перетнути промінь зору; перевірка виключенням;
   перевірка `in_front` — камера не повинна «перескочити» за деталь).
   Результат → `service_2021/calib/cameras/marker_2026-09-30/`.
4. Санітарна перевірка: проекція кільця `TOR_XL_1010_1` на фото має лягти на обід.
5. Наскрізний тест: набір з цих фото, розмітка лінії згину, розрахунок,
   порівняння з `TOR_XL_1010_1`. Архівні еталони v1–v23 записані в СТАРОМУ
   положенні — для методів 1/2 їх треба або перетворити, або перезаписати.
   Метод 3 з еталоном `TOR_XL_1010_1` на тому ж шоломі = перевірка чистої
   похибки вимірювання (правильна форма → чи кладе її фіт точно на місце).

  (`25_1`, `8_1`, `26_1`, `35_1`, `40_1`; розкид повторів 4.7–10.6 мм — нормально для
  іншого нахилу сопла). На двох фото пульта підписано «29», а точки 103 мм одна від одної;
  проекція на фото показала, що друга (`photo_..._10-04-37.jpg`) — це **28** (підпис на
  пульті помилковий). Виправлено в csv.
* **Стара калібровка (left/top) на нові координати пульта НЕ лягає**: на обох камерах
  зсув в один бік (~60–70 мм у просторі). Схоже, змінилась система координат робота

  всіх трьох камер, а не поправка.

  Бутстреп: впевнено прочитані номери → калібровка → передбачення решти → прилипання до
  плями → перевірка очима. Відкинуто хибні прилипання: back 12/29/30/34, left 34/36,
  top 2/10/17/24/34/38 (цифра підпису, край силуету або точки там нема).
* **Крок 3 зроблено** — `calib_joint.py --save` → `service_2021/calib/cameras/marker_2026-09-30/`.
  Чому не `calib_rays.py` поодинці: у top вісь сопла на маківці майже паралельна
  променю зору, «перетин прямих» нічого не тримає — підгонка ставила точку за 18–36 мм
  від сопла (на back/left стабільно ~10.5), повтори розходились на 4–6 мм. Спільна
  підгонка трьох камер (одна 3D-точка на всі ракурси, відступ ~10.5±2 мм) це прибрала.
  Перевірка виключенням (мм на деталі): back медіана 0.46 / макс 0.97,
  left 0.45 / 1.67, top 0.61 / 1.48. Фокуси закріплені — вільний фокус лише міняється
  з відстанню, нічого не покращує.
  `calib_rays.solve` теж полагоджено: кілька стартів + відкидання рішень ближче 1 м
  (back сідав у хибний мінімум з камерою за 400 мм від шолома).
* **Крок 4 зроблено** — кільце `TOR_XL_1010_1` на всіх трьох фото лягає правдоподобно
  (back/left — по фланцю з виступами вух, top — по контуру).
* **Крок 5 — поки синтетично** (`synth_method3.py`): правда = кільце еталона, розмітка =
  його проекція + шум оператора, старт зі збитої пози, підгонка як у Методі 3.
  Середня похибка лінії реза, мм (у дужках — медіана максимуму по кільцю):

  | розмітка | шум 3 px | шум 6 px | шум 3 px + зсув 1 мм |

  | стара, back+left | 0.56 (0.71) | 1.16 (1.59) | 1.39 (1.74) |

## Межа жорсткої підгонки еталона (14.10)

Якщо підігнати `TOR_XL_1010_1` прямо в 3D до правильних кілець 05.10 (поворот+зсув+масштаб,
ідеально, без камер і розмітки), лишається відмінність форми:
середня 1.0–1.3 мм, 90 % точок до 1.8–2.4 мм, гірша точка 2–3 мм (до `0510_1` лише 35–38 % точок <1 мм).
Це **нижня межа Методів 2/3** за будь-якої якості розмітки й калібровки: один еталон, підігнаний
як ціле, не повторює форму конкретного шолома. Щоб результат лягав «без доведення»,
лінію треба будувати по точках із самої розмітки (бажано з трьох ракурсів), а не
жорстким еталоном.

Якщо поверх жорсткої пози дозволити еталону **плавно вигинатися** (`floor_smooth.py`:
радіальний і висотний зсув як ряд Фур'є за кутом навколо кільця, K гармонік), межа падає:

| | K=0 (як Метод 3) | K=2 | K=6 |
|---|---|---|---|
| до `0510_1`: середня / макс / частка <1 мм | 1.20 / 2.91 / 42 % | 0.61 / 1.54 / 92 % | 0.53 / 1.33 / 95 % |
| до `0510_2` | 0.85 / 2.05 / 68 % | 0.67 / 1.80 / 91 % | 0.54 / 1.40 / 91 % |

K=2 — це по суті «різний масштаб уздовж і впоперек + сідло по висоті», жодних хвиль між
сусідніми точками. Тобто ідея «еталон + розумний масштаб/вигин по розмітці» знімає
більшу частину відмінності форми. Обмеження: тут підгонка йде до повного правильного кільця,
а розмітка бачить лише частину (спереду камери нема — там лише top згори),
тому в реальному методі вигин треба обмежувати там, де розмітки нема.

## Розмітка з різних ракурсів на реальних шоломах 05.10 (`exp_marks_views.py`, 14.10)

Розмітка = ТОЧНА проекція правильного кільця (без похибки оператора), еталон `TOR_XL_1010_1`.
Тобто тут лише геометрія камер + відмінність форми еталона. Похибка лінії різу, мм:

| | back+left, жорстко (Метод 3) | back+left+top, жорстко | back+left+top + вигин K=2 |
|---|---|---|---|
| `0510_1` середня / макс / <1 мм | 1.58 / 4.30 / 32 % | 1.38 / 3.06 / 40 % | 0.99 / 3.34 / 66 % |
| `0510_2` | 1.37 / 3.69 / 35 % | 0.98 / 2.12 / 57 % | 0.79 / 2.83 / 75 % |

Перевірено й через сам сервіс (набір `nabir-1005-001`, Метод 3, тимчасова розмітка з
правди — потім видалена): 1.50 / 3.53 мм — збігається. (Перший замір дав 3.8 мм — міряв
до ВЕРШИН правильного кільця, а вони через ~13 мм; міряти треба до лінії.)

Висновки:
* сам Метод 3 навіть за ідеальної розмітки — ~1.5 мм у середньому, до 3.5–4.3 мм;
* розмітка зверху (top) прибирає частину «ковзання по куполу»;
* top + плавний вигин — ~0.8–1.0 мм у середньому, 2/3–3/4 точок ближче 1 мм;
* лишаються окремі місця до ~3 мм — їх треба подивитись на фото (де саме).

## Перший наскрізний тест на РЕАЛЬНІЙ розмітці (14.10, `eval_real_marks.py`)

Оператор розмітив `nabir-1005-001/002` (= 05.10 _1/_2) у сервісі (left: чернетка → точки →
правка; back і весь _2 — від руки: жовта чернетка стояла далеко) і порахував Методом 3.

| | Метод 3 у сервісі: середня / 90 % / макс | <2 мм |
|---|---|---|
| `nabir-1005-001` | 1.78 / 2.89 / 3.84 мм | 69 % |
| `nabir-1005-002` | 2.08 / 4.02 / 4.95 мм | 63 % |

* Розмітка проти проекції правильної лінії різу: у середньому 0.8–1.5 мм, макс ~2.3 мм.
* Врахувати зазор «лінія згину ↔ лінія різу» (`exp_fold_offset.py`, сітка ±3 мм) — **не
  допомагає**: найкраще без зсуву, як і зараз.
* Плавний вигин лише з back+left — **гірше** (3.2 / 2.6 мм): без top він підганяється під шум.
* Ідеальний top (з правди — верхня межа) — 1.37–1.51 мм, <2 мм 72–85 %.
* Де похибка: найгірше там, де back бачить обід під гострим кутом (−135…−45° навколо осі,
  правий задній бік; до 3.9–4.9 мм на _2). Сектор −90…0° (правий перед) не бачить жодна
  камера. Камери: back і top — з боку 179°, left — 89°.

Наступний крок: top-контур автоматично (без ручної розмітки) у підгонку → «Метод 3+».
