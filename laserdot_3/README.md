## План (робота «під поточні камери»)

1. Розшифрувати 45 фото пульта → `points.csv` (точка, повтор, X..R, фото).
2. Пікселі пронумерованих точок на back/left/top → `pixels.json`
   (автодетект плям + звірка номерів очима, або `laserdot_2/mark.html`).
   Урок 18.08: переплутані підписи 13/19 зіпсували калібровку — перевіряти.
3. Калібровка променевою постановкою (`service_3030/exp_marker_calib.py`:
   промінь інструмента має перетнути промінь зору; перевірка виключенням;
   перевірка `in_front` — камера не повинна «перескочити» за деталь).
   Результат → `service_2021/calib/cameras/marker_2026-09-30/`.
4. Санітарна перевірка: проекція кільця `TOR_XL_1010_1` на фото має лягти на обід.
5. Наскрізний тест: набір з цих фото, розмітка лінії згину, розрахунок,
   порівняння з `TOR_XL_1010_1`. Архівні еталони v1–v23 записані в СТАРОМУ
   положенні — для методів 1/2 їх треба або перетворити, або перезаписати.
   Метод 3 з еталоном `TOR_XL_1010_1` на тому ж шоломі = перевірка чистої
   похибки вимірювання (правильна форма → чи кладе її фіт точно на місце).

## Межа жорсткої підгонки еталона (14.10)

Якщо підігнати `TOR_XL_1010_1` прямо в 3D до правильних кілець 05.10 (поворот+зсув+масштаб,
ідеально, без камер і розмітки), лишається відмінність форми:
середня 1.0–1.3 мм, 90 % точок до 1.8–2.4 мм, гірша точка 2–3 мм (до `0510_1` лише 35–38 % точок <1 мм).
Це **нижня межа Методів 2/3** за будь-якої якості розмітки й калібровки: один еталон, підігнаний
як ціле, не повторює форму конкретного шолома. Щоб результат лягав «без доведення»,
лінію треба будувати по точках із самої розмітки (бажано з трьох ракурсів), а не
жорстким еталоном.

Якщо поверх жорсткої пози дозволити еталону **плавно вигинатися** (`floor_smooth.py`:
радіальний і висотний зсув як ряд Фур'є за кутом навколо кільця, K гармонік), межа падає:

| | K=0 (як Метод 3) | K=2 | K=6 |
|---|---|---|---|
| до `0510_1`: середня / макс / частка <1 мм | 1.20 / 2.91 / 42 % | 0.61 / 1.54 / 92 % | 0.53 / 1.33 / 95 % |
| до `0510_2` | 0.85 / 2.05 / 68 % | 0.67 / 1.80 / 91 % | 0.54 / 1.40 / 91 % |

K=2 — це по суті «різний масштаб уздовж і впоперек + сідло по висоті», жодних хвиль між
сусідніми точками. Тобто ідея «еталон + розумний масштаб/вигин по розмітці» знімає
більшу частину відмінності форми. Обмеження: тут підгонка йде до повного правильного кільця,
а розмітка бачить лише частину (спереду камери нема — там лише top згори),
тому в реальному методі вигин треба обмежувати там, де розмітки нема.

## Яка деформація еталона потрібна (`exp_shape_modes.py`, 14.10)

Найкраща підгонка в 3D (без камер), еталон → правда, середня мм:

| модель | 1010_1→0510_1 | 1010_1→0510_2 | v1→v21…v25 (старий архів, інші шоломи) |
|---|---|---|---|
| жорстко | 1.32 | 0.97 | 1.28–2.17 |
| + однаковий масштаб | 1.34 (−0.05 %) | 0.98 (−0.13 %) | 1.00–1.82 |
| + окремо довжина/ширина | 1.10 (довжина −0.9 %, ширина +0.9 %) | 0.76 (−0.8 % / +0.6 %) | 1.18–1.67 (довжина −1.1…−2.0 %) |
| + плавний вигин K=2 | **0.63** | **0.66** | **0.73–0.94** |

* Однаковий масштаб майже нічого не дає — шоломи не «більші/менші», а трохи **інші за
  пропорціями**: коротші/довші на 1–2 % (2.5–5 мм на довжині) і різна висота вух відносно
  лоба/потилиці. K=2 описує саме це (довжина/ширина + «сідло» по висоті) — і працює
  однаково на нових і старих шоломах, тобто не підігнано під два набори.
* Висновок 5056 (10.08) «форми 1 і 4 за лінією різу не відрізняються» — узгоджується.
* Нахил площини кільця між шоломами — **5–15°** (1010_1 5.0°, 0510_1 13.4°, 0510_2 5.6°).
  Тому контур зверху НЕ можна вважати лінією згину: при нахилі силует згори утворюють
  різні частини купола. Правильно — порівнювати силует згори з силуетом **3D-моделі
  шолома в тій самій позі** (нахил тоді врахований автоматично).
* У старому архіві макс ~10 мм у всіх моделях — одна й та сама точка (ймовірно, біля
  пірсингу), не форма; не розбирався.

## Чесна емуляція з видимістю і прототип Методу 4 на реальній розмітці (14.10)

* **Видимість лінії** (`exp_fold_visibility.py`, промінь до камери проти 3D-моделі; поріг
  20 мм — інакше «закривала» власна стінка моделі): back ~51 %, бокова ~51 %, top ~61 %,
  уявна бокова з протилежного боку ~54 %. Top і протилежна бокова бачать ТІ САМІ ділянки
  (задня чверть з протилежного боку). Перша емуляція брала для top усе кільце — завищена.
* **Чесна емуляція** (`exp_marks_visible.py`, ідеальна розмітка лише видимих ділянок):
  back+бокова 1.42–1.50 мм / <2 мм 72–74 %; +top +вигин 0.83–0.90 / 94–97 %;
  +протилежна бокова +вигин 0.82–0.87 / 92–94 %; обидві +вигин 0.74–0.75 / 98 %.
  Тобто **перенести top набік нічого не дає** порівняно з розміткою згори.
* **Край шолома на фото згори проти правильної лінії** (`exp_top_edge.py`, пошук
  найрізкішого перепаду вздовж нормалі): зсув −0.2…−0.7 мм, розкид σ 1.0–1.3 мм, викиди
  до 4–6 мм (волокна юбки), ззаду край на 1–2 мм усередину. Тобто край згори ≈ лінія з
  точністю ~1 мм — порівняно з ручною розміткою.
* **Прототип Методу 4** (`exp_method4_proto.py`, без підглядання у відповідь: старт —
  Метод 3 на реальній розмітці, край згори шукається автоматично, двічі):

| | Метод 3 | М4 жорстко (trim) | М4 + вигин (trim) |
|---|---|---|---|
| nabir-1005-001 | 1.78 / макс 3.84, <2 мм 69 % | 1.65 / 3.50, 75 % | 1.42 / 3.52, 77 % |
| nabir-1005-002 | 2.08 / макс 4.95, <2 мм 63 % | 1.46 / 2.98, 74 % | 1.67 / 2.77, 68 % |

  Покращення ~20–30 % у середньому і помітно по найгірших точках, але не до 0.8 мм:
  тепер межа — точність самої розмітки (~1 мм) і краю згори (~1 мм).
  Важливо: нев'язка «лінія → розмітка» (як у Методі 3) тягне видимі, але НЕ розмічені
  оператором ділянки до кінця розмітки — з вигином це ламало результат (до 7 мм). Варіант
  `trim` (не рахувати біля кінців розмітки) це прибирає. У Методі 3 на сервісі цей ефект теж
  є, просто без вигину слабший.

## Метод 4 (експеримент) у сервісі (14.10)

`service_2021/methods/method4/run.py` — Метод 3 + край шолома на фото згори (автоматично,
поруч з поточною лінією) як третій ракурс; нев'язка «лінія → розмітка» не рахується біля
кінців розмітки. Плавний вигин є (`--bend так`), але вимкнений: давав викиди до 7 мм там,
де розмітки нема. Перевірка — `eval_methods.py` (збирає вхід так само, як сервіс):

| | Метод 3 | Метод 4 |
|---|---|---|
| nabir-1005-001 | 1.78 / макс 3.84 / <2 мм 69 % | 1.58 / 4.03 / 74 % |
| nabir-1005-002 | 2.08 / 4.95 / 63 % | 1.45 / 2.69 / 80 % |
| v21–v25 (стара розстановка), середнє | 2.77 / 5.78 / 35 % | 2.78 / 8.51 / 49 % |

На старих шоломах згори видно фланець, що стирчить на 3–5 мм за лінію згину, а пошук краю
часом чіпляється за шов на куполі — найгірші точки там гірші. Варіанти «край лише не
пускає за силует» (`--top one`) і асиметричний — гірші (через шви). Тому — «експеримент».
Наочно: `out_compare/` (зелена — правильна, червона — Метод 3, синя — Метод 4),
перевірка калібровки по 40 точках — `show_calib_points.py` → `out_calib_check/`.

### Метод 4: розтяг по довжині/ширині (14.10)

Після перегляду оператором (Метод 4 на 1005-001: «збоку масштаб не той — стирчить біля лоба й
потилиці; згори так само») додано окремий масштаб уздовж (лоб–потилиця) і впоперек (вухо–вухо)
шолома, ±3 %. Розтяг уздовж від центру майже не рухає вуха. Без обмеження загального масштабу
підгонка «хитрувала» (v25: загальний 95 % + ширина +3 %) — тепер загальний ±2 %.

| | Метод 3 | М4 без розтягу | М4 + розтяг |
|---|---|---|---|
| 1005-001 | 1.78 / 3.84 / 69 % | 1.58 / 4.03 / 74 % | **1.44 / 2.74 / 86 %** |
| 1005-002 | 2.08 / 4.95 / 63 % | 1.45 / 2.69 / 80 % | **1.34 / 2.63 / 85 %** |
| 7 шоломів, середнє | 2.53 / 5.4 / 44 % | 2.42 / 7.0 / 57 % | **2.21 / 5.9 / 59 %** |

(середня мм / найгірша точка мм / частка <2 мм)
